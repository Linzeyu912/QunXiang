## 三、服务器部署规划

### 现状 → 目标

现在：Windows 本地 + Docker postgres + fs 对象存储 + start.bat 双击启动，单人单机。
目标：Linux 服务器长期运行，多人注册使用（公共书库天然多用户：每个新用户自动获得预置书）。

### 架构（全部走 Docker Compose）

```
                 ┌─────────────┐
   HTTPS 443 →   │ nginx/caddy │  反向代理 + TLS 证书（Caddy 自动签）
                 └──┬───────┬──┘
          /api  →   │       │   →  /  静态前端
              ┌─────▼──┐  ┌─▼────────┐
              │  api   │  │ web(dist)│  api: node dist/index.js
              │ (node) │  │ (nginx)  │  web: pnpm build → 静态文件
              └───┬────┘  └──────────┘
        ┌─────────┼──────────┐
   ┌────▼───┐  ┌──▼─────┐  ┌─▼──────┐
   │postgres│  │ objects│  │（可选） │
   │  15    │  │ volume │  │pgBouncer│
   └────────┘  └────────┘  └────────┘
```

### 部署前必须改的配置

| 项 | 现在（开发） | 生产要求 |
|---|---|---|
| `JWT_SECRET` | 硬编码默认值 | 随机 64 字符，环境变量注入 |
| `KEY_VAULTS_SECRET` | 默认值 | 随机生成并**固定备份**——丢了所有加密 LLM 配置报废（7/24 已踩过） |
| postgres 密码 | `change_me_in_production` | 强密码，仅容器网络内可达（不暴露 5432 到公网） |
| `ALLOWED_ORIGINS` | localhost:5173 | 正式域名 |
| `OBJECT_STORAGE_PROVIDER` | fs（本地目录） | 数据量大上 S3/MinIO；小站 fs+volume 即可 |
| `NODE_ENV` | development | production（api 跑 `pnpm build && node dist/index.js`） |
| LLM/图片配置 | 前端设置页 | 服务器上首次部署后在设置页录入一次（加密存盘）；或直接把 `.qunxiang-config.encrypted` 带过去（需同一 KEY_VAULTS_SECRET） |
| Reve 生图 | 代理 7897 | 服务器若在境外（或本身非限制区）可去掉 IMAGE_PROXY；境内服务器必须配代理 |

### 部署步骤（预估半天）

1. **服务器准备**：1 台 2C4G VPS 起步（LLM 调用在外部 API，本机不吃算力；postgres+node 足够），装 Docker + compose 插件
2. **代码**：`git clone`（seed-library 随仓库，预置书自动就位）→ `pnpm install --frozen-lockfile`
3. **构建**：`pnpm --filter @qunxiang/api build`；web 包 `pnpm build` 出 dist
4. **compose**：在现有 docker-compose.yml 上加 api + web(nginx) 两个服务，postgres 去掉端口映射（只在内部网络）
5. **环境**：api/.env 按上表生产化；`prisma migrate deploy`
6. **反代/TLS**：Caddy 最省事（自动证书），`api.example.com → api:3000`、`example.com → web:80`
7. **验证**：注册测试账号 → 应自动获得 2 本预置书 → 上传一本书跑提取 → 生图一张
8. **运维**：`docker compose up -d` + restart: unless-stopped；备份 = 每日 `pg_dump` + 对象存储目录 rsync（或 S3 版本控制）

### 多用户注意事项（已核实过）

- **注册物化是同步的**（注册请求内完成），并发注册安全：对象存储内容寻址去重，DB 行各自独立
- **BackgroundJob worker 在 api 进程内**：单实例部署无问题；**不要直接开多个 api 副本**（任务会重复消费，虽然 lease 机制兜底，但没验证过）。要扩容先单实例顶着
- **限流**：注册 5 次/分钟/IP 已有；公网建议 nginx 层再加全局限流
- **数据隔离**：所有路由 owner-scoped（ownership 集成测试覆盖），分享走邮箱+分享码双因子

### 风险与回退

- **数据库**：pg_dump 每日备份到对象存储/另一台机器；迁移用 `prisma migrate deploy`（start.bat 同款，已验证）
- **回滚**：代码回滚 git + DB 不回滚（前向迁移）；书包更新不触碰用户已物化的副本（互不影响）
- **监控**：最低限度 `docker compose ps` + `/health` 探活；后续可上 uptime-kuma
