# 公共素材库 · 数据模型与 API 设计（阶段一 MVP）

> 2026-07-28 初稿。目标：用户把自己书里的素材（实体卡 + 图片 + 提示词）发布到公共池，
> 其他用户实时浏览、拿取到自己书库。与"点对点分享"（BookShare，邮箱+分享码）并列，
> 本功能是**广播式公开**。
>
> 前置共识：此形态需要服务器（7×24 在线、共享 DB + 对象存储），部署按
> 《遗留事项与部署规划-2026-07》第三部分执行；本设计只覆盖功能本身。

---

## 一、核心设计决策

### 1. 发布 = 拍快照，与源实体解耦（最重要）

发布时把实体的当前内容**完整复制**进 `PublicAsset.payload`（JSON），图片只建引用不复制字节
（AssetObject 内容寻址天然去重）。之后发布者改书、删书、重新提取，都不影响公共池里的副本；
下架只改状态不删数据。

- ✅ 对比"引用源实体"方案：源实体被删/改会带着公共池内容变动甚至 404，级联复杂，否决。
- ✅ 与 BookShare 用 AssetSnapshot 的思路一致：分享/发布出去的永远是不可变快照。

### 2. 发布单元 = 实体卡（character / location / item）

一张实体卡包含：实体字段（名称/别名/描述/视觉设定/年龄阶段提示词 variants）+ 图片画廊引用。
不单独发布裸图片或裸提示词（它们依附实体才有意义；后续有需求再开 `image` 类型）。

### 3. 拿取落点 = 拿取者指定一本自己的书

拿取时选择目标书，实体以 **PENDING** 状态进入该书的待审核列表（图片引用一并带入），
走现有审核流。不做独立"素材箱"概念（MVP 控制范围，阶段二再议）。

### 4. 审核策略 = 后置

MVP 不做前置审核：发布即公开。兜底手段 = 发布者下架 + 举报入口（阶段二）。
理由：早期用户即开发者熟人圈，前置审核成本高收益低；但**举报字段预留**。

## 二、数据模型（Prisma 新增 3 表）

```prisma
/// 公共素材：实体卡的不可变快照。payload 自包含，不依赖源书/源实体存活。
model PublicAsset {
  id           String   @id @default(uuid()) @db.Uuid
  publisherId  String   @db.Uuid
  kind         String   // character | location | item
  name         String   // 实体名（列表页主标题，冗余自 payload 便于检索）
  summary      String?  // 一句话介绍（列表页副标题，发布时可编辑，默认取 description 前 80 字）
  tags         Json     @default("[]") // string[]，发布者自填，如 ["古风","少女","武器"]
  payload      Json     // 实体完整快照：字段集 + visualDetails + promptVariants（结构见下）
  status       String   @default("published") // published | unlisted（下架）| removed（管理员）
  takenCount   Int      @default(0)           // 冗余计数，排序用，由 PublicAssetTake 事务维护
  createdAt    DateTime @default(now()) @db.Timestamptz(3)
  updatedAt    DateTime @updatedAt @db.Timestamptz(3)

  images       PublicAssetImage[]
  takes        PublicAssetTake[]

  @@index([status, kind])
  @@index([publisherId])
  @@index([status, takenCount]) // 热度排序
}

/// 公共素材的图片引用：字节不复制，指向 AssetObject（内容寻址）。
/// objectKey 冗余存储便于直接签 URL；AssetObject 行保证对象不被引用计数回收。
model PublicAssetImage {
  id             String @id @default(uuid()) @db.Uuid
  publicAssetId  String @db.Uuid
  publicAsset    PublicAsset @relation(fields: [publicAssetId], references: [id], onDelete: Cascade)
  assetObjectId  String @db.Uuid
  objectKey      String
  mime           String
  bytes          Int
  aspectRatio    String?
  stage          String?  // 年龄阶段（与 EntityImage.stage 对齐）
  isPrimary      Boolean  @default(false)
  sortOrder      Int      @default(0)

  @@index([publicAssetId])
}

/// 拿取记录：计数、防重复拿取提示、后续"我的拿取"列表。
model PublicAssetTake {
  id          String   @id @default(uuid()) @db.Uuid
  publicAssetId String @db.Uuid
  publicAsset PublicAsset @relation(fields: [publicAssetId], references: [id], onDelete: Cascade)
  takerId     String   @db.Uuid
  targetBookId String  @db.Uuid   // 拿取到哪本书
  createdAt   DateTime @default(now()) @db.Timestamptz(3)

  @@index([takerId])
  @@index([publicAssetId])
}
```

**payload 结构**（以 character 为例，location/item 按各自字段集裁剪）：

```json
{
  "name": "韩立",
  "aliases": ["韩老魔"],
  "description": "……",
  "visualDetails": { "hair": "……", "eyes": "……" },
  "promptVariants": [
    { "stage": "少年", "prompt": "……", "negativePrompt": "……" }
  ],
  "sourceBookTitle": "凡人修仙传150章"
}
```

- 不含任何 userId / bookId / chapterRef（章节定位对拿取者无意义，也避免泄露源书结构）
- `sourceBookTitle` 发布时可勾选是否展示（默认展示，算是对来源的署名）

## 三、API 设计（全部需登录，前缀 `/public-assets`）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/public-assets` | 发布。body: `{ bookId, entityType, entityId, summary?, tags?, showSource? }`。服务端校验书籍归属 + 实体存在且 **APPROVED**（未审核的素材不许发布），抓快照+收集该实体的 EntityImage → 建 PublicAsset + PublicAssetImage（仅引用 objectKey 已存在的图） |
| GET | `/public-assets` | 浏览公共池。query: `kind`, `tag`, `q`（名称/简介模糊）, `sort=new|hot`（默认 new）, `cursor`（游标分页，每页 20）。只返回 `status=published`，不含 payload 全文（列表用摘要+主图签名 URL） |
| GET | `/public-assets/mine` | 我发布的（含已下架），发布者管理入口 |
| GET | `/public-assets/:id` | 详情：完整 payload + 全部图片签名 URL + 发布者昵称 + takenCount |
| POST | `/public-assets/:id/take` | 拿取。body: `{ targetBookId }`。校验目标书归属；事务内：建实体（status=PENDING，名称冲突时自动加后缀 `（公共库·韩立）`）→ 建 EntityImage 引用 → 建 PublicAssetTake → takenCount+1 → AuditLog |
| POST | `/public-assets/:id/unlist` | 下架（仅发布者）。status→unlisted，公共池不再可见；已有拿取记录不受影响 |

统一约定（沿用现有规范）：
- 无权限/不存在一律中文 404（`素材不存在或已下架`），不泄露资源存在性
- 限流：发布 10 次/分钟/账号，拿取 20 次/分钟/账号（防刷屏）
- 所有写操作记 AuditLog（`PUBLIC_ASSET_PUBLISHED / UNLISTED / TAKEN`）

**图片公开访问**：复用 `/objects/dl` HMAC 令牌机制，列表/详情接口直接返回签好 10 分钟的
URL（与书内图片同一套）。令牌不绑定用户，公共图天然可公开——无需新增公开端点。

## 四、前端页面

1. **公共素材库页** `/public`：顶部 Tab（角色/场景/道具）+ 标签筛选 + 搜索框 + 排序（最新/最热），
   卡片 = 主图 + 名称 + 简介 + 发布者昵称 + 拿取数。点卡片进详情（图片画廊 + 提示词 variants 展示
   + [拿取到我的书库] 按钮 → 弹窗选目标书）。
2. **发布入口**：实体审核页/实体详情加 [发布到公共库] 按钮（仅 APPROVED 实体可点），
   弹窗编辑 summary/tags/是否署名来源书。
3. **我的发布**：公共素材库页内一个 Tab，可下架。

导航：顶部导航加"公共素材库"，与"书库 / 分享给我"并列。

## 六、风险与注意点

- **对象回收**：现有对象存储按引用计数回收时，必须把 PublicAssetImage 计入引用，
  否则公共图会被误清（实现时先查回收逻辑，补引用来源）。
- **重复拿取**：同一素材允许拿取到不同书；拿取到同一本书时按"书名+实体名"查重，弹窗提示"已拿取过"。
- **隐私**：payload 不含任何账号信息；发布者昵称展示用 User.name（注册时填的），不展示邮箱。
- **部署依赖**：本地单机也能开发测试（多注册几个账号即可模拟多用户），
  但"别人同时能看到"的正式使用必须先完成服务器部署。
